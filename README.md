# ROCCO RUN: THREE WORLDS

**ENGR-126 Project 20b**, a side-scrolling platformer inspired by Mario, written in Python with Pygame.

Help **Rocco** (an original hero with an orange cap, teal shirt and navy overalls) run, jump and stomp through three worlds, then raise the flag and enter the castle at the end of each one. All the graphics, sound effects and music are generated by the code. There are no image or audio files.

The same single file runs on a Windows laptop (PyCharm) and in a web browser (built with pygbag and published on Netlify).

---

## Features

- **Three worlds**
  - **1-1 Overworld**: green hills, pipes, bricks, question blocks and walking enemies only. An easy start.
  - **1-2 Underground**: a dark cave with a stone ceiling, raised terraces, ledges and spiky enemies.
  - **1-3 Sky World**: floating cloud platforms over a bottomless sky. Clouds are one-way: you jump up through them and land on top.
- **Responsive movement**: acceleration, a walking and a running top speed, friction, skidding, and a higher jump when running.
- **Jump that feels good**: hold Space to jump higher, let go early for a short hop. Includes coyote time (0.1 s) and jump buffering (0.12 s).
- **Blocks**: question blocks give a coin or a mushroom, hidden blocks show up when hit from below, and big Rocco breaks bricks into flying pieces.
- **Power-up**: a mushroom makes Rocco big. If big Rocco gets hit, he shrinks and blinks for 2 seconds while he can't be hurt.
- **Enemies**
  - **Nutling** (a walking acorn): stomp it. Each extra stomp in the same jump doubles the points.
  - **Spikeback** (a red spiky shell): it cannot be stomped. Avoid it, or knock it out by bumping the block it stands on.
- **End of each world**: a higher grab on the flagpole gives more bonus points (100 to 5000). Leftover time turns into points.
- **Score, coins, lives and timer**: 100 coins give an extra life. The best score is saved.
- **Screens**: title screen, world intro, pause menu, game over and victory.
- **Original sound**: sound effects and three looping songs (one per world), all made in code.

## Requirements

- Python 3.10 or newer
- `pygame` 2.6 or newer
- `pygbag` (only to build the web version)

Everything is listed in `requirements.txt`.

---

## Running it in PyCharm

1. Put `rocco_run.py` and `requirements.txt` in your PyCharm project folder.
2. Open PyCharm's **Terminal** tab at the bottom of the window. It uses your project's Python, unlike Command Prompt.
3. Install the packages:
   ```
   pip install -r requirements.txt
   ```
   (Only need the desktop version? `pip install pygame` is enough.)
4. Right-click `rocco_run.py` and choose **Run 'rocco_run'**.

The window can be resized. The game scales up and keeps its 960 x 600 shape.

**Best score:** saved in `rocco_run_save.json`, in the same folder as `rocco_run.py`. Delete that file to reset it.

## Publishing on the web (pygbag + Netlify)

1. Make a new folder, for example `rocco_web`.
2. Copy `rocco_run.py` into it and **rename the copy to `main.py`** (pygbag needs that name).
3. In PyCharm's Terminal, go to the folder that *contains* `rocco_web`, then test it in your browser:
   ```
   pygbag rocco_web
   ```
   Open `http://localhost:8000`, click the page, and play.
4. Build the website:
   ```
   pygbag --build rocco_web
   ```
   The finished site is in `rocco_web/build/web`.
5. Create a free account at [netlify.com](https://www.netlify.com). Open **app.netlify.com/drop** and drag the `web` folder onto the page. Netlify gives you a link you can share.

**Browser notes**
- You click the page once to start. That click also turns the sound on, because browsers block sound until you interact with the page.
- In the browser, the best score is saved in the browser's localStorage, so each browser and device keeps its own.
- The page needs an internet connection, because pygbag loads the Python/Pygame runtime online.
- The browser fits the game to the window and keeps its shape.
- Esc opens the pause menu. Closing the tab simply ends the game.

## How the program works

Everything is in one file, split into nine labelled sections:

| # | Section | What it does |
|---|---|---|
| 1 | Imports and configuration | Screen size, physics values, scoring, keys. Edit the game's feel here. |
| 2 | Levels and tile dictionary | The three text maps, `TILE_TYPES`, and a level checker. |
| 3 | Helper functions | Math helpers, best-score saving (JSON file or localStorage). |
| 4 | Player class | Movement, speed limit, skid, jump, coyote time, jump buffer. |
| 5 | Enemy and item classes | Enemies, mushrooms, coins, particles, floating score text. |
| 6 | Collision and physics | `Level` class and `move_and_collide()`, shared by every moving object. |
| 7 | Camera and rendering | Forward-only camera, the drawn artwork, parallax backgrounds. |
| 8 | Sound and music | Waveforms built from numbers and played with `pygame.mixer.Sound(buffer=...)`. |
| 9 | Main loop and screens | `Game` class (states, menus, HUD) and `async def main()`. |

**Physics.** Speeds are in pixels per second and gravity in pixels per second squared. Every frame uses the elapsed time `dt`, capped at 1/30 s, so the game plays the same at any frame rate. The hero only speeds up while below the speed limit and is then clamped, so he can never go faster than `RUN_SPEED` (400). Half the gravity is applied before moving and half after, so a full jump reaches the height the physics formula predicts (about 174 px, a little over 4 tiles).

**Collisions** happen in this order: move sideways, then fix wall hits, then move up or down, then fix floor and ceiling hits, then check one-way clouds separately. When Rocco hits blocks from below, the block nearest the center of his head is the one that reacts. Blocks a body already overlaps are ignored, so nothing gets stuck inside a wall.

**Camera.** The camera only moves forward. Rocco cannot walk back off the left edge, and only tiles on screen are drawn.

**Web-ready.** The main loop is `async def main()`, with `await asyncio.sleep(0)` every frame so the browser never freezes. `sys.platform == "emscripten"` tells the game it is running in a browser. There it uses localStorage and never tries to close the window.

**Starting physics values** (top of the file):
```
GRAVITY = 2600    JUMP_SPEED = 950    WALK_SPEED = 250    RUN_SPEED = 400
ACCEL = 1300      LIVES = 3           TIME_LIMIT = 300    TIME_RATE = 2.0
```
`TIME_RATE = 2.0` means the timer drops 2 units every real second, so the 300 timer lasts 150 seconds.

## Editing the levels

The maps `LEVEL_1`, `LEVEL_2` and `LEVEL_3` are near the top of the file. Each one is **exactly 15 text rows**, all the same length, and every character is one 40 x 40 tile. Rows 13-14 are normally ground, and the hero stands in row 12.

| Char | Meaning |
|---|---|
| `.` | Empty air |
| `#` | Solid ground |
| `B` | Breakable brick |
| `?` | Question block (coin) |
| `M` | Question block (mushroom) |
| `H` | Hidden block (coin), invisible until hit from below |
| `{` `}` | Top of a pipe (left, right half) |
| `[` `]` | Pipe body below the top (left, right half) |
| `=` | One-way platform (a cloud in the Sky World) |
| `o` | Coin |
| `E` | Regular walking enemy |
| `X` | Spiky enemy |
| `S` | Player start |
| `F` | Flagpole base block (put it in row 12) |
| `C` | Castle, bottom-left tile (5 x 5 tiles, put it in row 12) |

A 3-tall pipe looks like this:
```
{}
[]
[]
##
```

**Fairness rules** for the starting physics: gaps of no more than 3 tiles, pipes and walls of no more than 4 tiles, sky clouds at least 7 tiles wide, and height changes between platforms of no more than 2 tiles.

When the game starts, it checks every map and prints warnings in the PyCharm console: wrong row count, missing `S`/`F`/`C`, gaps too wide, pipes too tall, clouds too narrow. After editing a map, always play it to make sure every jump works.

## Troubleshooting

| Problem | Fix |
|---|---|
| `ModuleNotFoundError: No module named 'pygame'` | Pygame went into a different Python. Run `pip install pygame` in **PyCharm's Terminal**, or add it under *Settings > Project > Python Interpreter > +*. |
| `pip install pygame` fails while building | Your Python may be too new for pygame. Try `pip install pygame-ce`; the code works the same with it. Or switch the PyCharm interpreter to Python 3.11 / 3.13. |
| No sound on the desktop | Check you didn't press **M** (the corner says *M: MUTED*). Check Windows volume. If no audio device is found, the console prints *"Sound is off"* and the game still runs. |
| No sound in the browser | Click the game page first. Browsers block sound until you interact with the page. |
| `ValueError: Level ... must have exactly 15 rows` | A map was edited and lost or gained a row. Every level needs 15 rows of equal length. |
| Hero can't make a jump after you edited a level | Check the fairness rules above. |
| Web page stays black or stuck loading | Make sure the file in the folder is named `main.py`. Test with `pygbag rocco_web` first, then press **F12** in the browser to read errors in the Console tab. |
| `pygbag` is not recognized | Run `pip install pygbag` in PyCharm's Terminal, or run it as `python -m pygbag rocco_web`. |
| Best score won't reset | Desktop: delete `rocco_run_save.json`. Browser: clear that site's data. |
